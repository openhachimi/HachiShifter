# 日语 ASR → TIFA 自动注音

## 入口和范围

- 素材管理器：素材文件夹的右键菜单“日语 ASR / TIFA 自动注音…”，处理该文件夹下支持的录音（含子目录）。
- 共用素材标注概览：“为当前录音生成日语注音…”，只处理当前音频。未保存的表单／草稿必须先用既有保存或放弃操作处理，不会暗中丢弃。
- 日语专用。输出为字典中的罗马音发音组，不是汉字／假名的词法转写，也不是多语言识别器。
- 页面顶部说明日语专用及必须人工检查，不再要求日语确认勾选。底部三个按钮：**推理**始终重新识别并对齐，不受人工栏旧文本影响；**仅推理识别**只运行 ASR 和词典分组，回填音节，不运行 TIFA／不生成可保存标注；**仅推理对齐**只读取“人工输入/修正”栏运行 TIFA，不调用 ASR。输入为空会明确提示先输入或先识别。
- 推理或识别成功时，将规范音节（如 `so re`）填入人工栏。文件夹结果使用明确的“人工输入对应录音”选择，每个录音保留自己的文本；仅对齐只处理该录音，不将一条手工序列混用于全部文件。完整推理中对齐失败，也保留已识别的音节供修正。
- 对齐成功后使用报告上方的“确认标注并编辑”进入实际确认框；取消不写文件。确认原子保存后，先释放发布门闩，再将原干净人工编辑窗口刷新为确切新变体的会话和指纹；未选中的干净作者窗口只更新自身原变体令牌，脏稿／音符局部上下文不被悄悄替换。此后原窗口可实际修改并保存。现有作者变体、工程音符和 PCM 不按路径自动重绑定／覆盖。

## 资源布局

运行时从可执行文件旁发现模型，默认目录：

```text
bin/models/japanese_annotation/
  asr/
    model.onnx
    model.meta.json
    phoneme_vocab.json
    PROVENANCE.md
  tifa/
    spectrogram.onnx
    model.onnx
    config.json
    vocabulary.json
    japanese_dict_full.txt
    LICENSE.code.txt
    LICENSE.model.CC-BY-NC-SA-4.0.txt
    PROVENANCE.md
  manifest.json
```

推理是原生 C++／ONNX Runtime；不启动 Python。Python 仅用于开发阶段的官方模型离线导出／检查等工具工作，不是此功能的运行依赖。

ASR 为用户原有 exp12 部署模型：16 kHz FLOAT32 `[B,S]` → INT64 `pred_ids[B,F]`，CTC 合并产生音素／音拍序列。CTC 帧宽不当作强制对齐结果。

TIFA 使用固定源码版本 `d246be1cc2e202613213ca60a4e5d35e71a2fb6a` 的官方导出图。48 kHz 波形经 spectrogram 图产生特征，再用 model 图生成音频／音素余弦相似度；C++ 采用该版本 `decode_alignment_flat`，不套用旧版通用解码器，不强插 SPACE，不把原始余弦取 log-softmax。

## 发音与时间定义

使用官方日语字典展开识别音拍并按最长音素组组合发音，最终保存单位为音节，不是音素：`s o r e` 保存为 `so`、`re` 两条。保留已识别的字典拼写；原子音素存在 `re/le` 同音拼写时，使用识别模型词表中唯一支持的规范名字。仍有多个规范候选才要求明确输入，不按录音文件名猜。`N` 不小写成辅音 `n`。官方字典未覆盖的 `fyu` 等不凭字符串猜拆。

时间参照 [TextGrid2oto](https://github.com/xiaobaijunya/TextGrid2oto/tree/1e8e9199b676f6ce22b59f87bfb3ef7c57ebe252) 的音素合组与 CV/CVVC 计算事实：多音素组的 middle 为第一个音素终点，单音素组为起点；先行放在 middle，固定区延入元音约三分之一，交叉约为辅音先行长度的一半。纯元音使用有界的短进入窗。原生素材保留整个实际音节范围，不照搬 UTAU CVV 预设的首尾裁剪。不复制或嵌入该 GPL 工具代码；本实现通过既有原生时间权威独立实现相应计算。`cl` 等无元音组保持过渡／保护语义。简化辅音关闭，不把音素或模型帧当手动 V 切分。余弦指标不是正确率或校准概率。

## 连续音组合与实际外沿

系统按现有素材来源选择工作：优先实际多字整句，其次实际素材＋已登记的 V_C 衔接音＋素材，再退回单音。当前是用户明确选择实际素材／发音，不是新建一个会按别名伪造音频的自动歌词合成器；没有真实 `e_g` 就不会生成假录音。

新的可选 `nativePronunciationEdges` 保存源坐标进入／退出窗和终止位置，普通 P/C/overlap 仍是原来的时间定义。实际使用 `a_b_c` 只启用 a 进入与 c 退出，`a_b` 启用 a/b 两端，单独 b 才启用 b 两端；同源内部保持平坦。是否连续由明确的行链接、同一录音和当前源／目标锚点共同证明，不凭文件名、时间相邻、音高滑音图或编辑关联布尔值猜测。当前保留片段落在原有合法标注范围内时，使用与源编辑相同的显式裁剪规划投影进入／退出窗口；切点位于淡化窗中时，启用的外沿窗口沿整个同源组合时钟跨切片连续作用，不逐片重新起算。无效原始资料、错误身份或超出原始标注范围的未知上下文仍明确拒绝，不放宽持久化校验。

此策略仅对带可选资料的素材启用。旧工程没有此资料时保持原路径；显式作者淡入／淡出／包络保留并乘性组合。新的边界增益通过既有统一混音权威作用于实时／离线输出，不重写音高或源时间图。必须在共用编辑器复核粗标注与实际使用组合。

输入目前限定每段 0.05–60 秒，超过时明确拒绝该文件，不静默截断。缺失模型、非法张量／字典、未知音素、被跳过的音素、源文件变更等不生成伪边界。静音拒绝，不依据文件名猜歌词。

### 重叠支持区的整句／子集放入

同一精确音频变体的发音支持区可能重叠。放入操作保留完整源标注快照，另规划不重复播放的实际所有权：严格按源顺序的同源重叠，使用相交支持区内的入音 P，或入音的明确源起点作为边界；不是猜文件名、音高或任意中点。整句物理并集只播放一次，窗口仍由实际选中的首末发音启用。`a_b_c`、`a_b`、`b_c` 或单音由每次真实选择独立决定，不依赖上一回选择。

没有 profile 的旧行，只有完整已登记变体存在严格单调重叠链且明确配置了非零 overlap，才在项目放入时派生有界默认窗，源 OTTO 不改。该链中的单音选择也按自身两端处理；完全不重叠的旧资料仍不自动启用新策略。逆序重叠、嵌套／相同范围、重复 ID 或跨变体模糊覆盖仍原子拒绝。实际放入后的源连续关系与源文档的后继字段不是同一意图：对裁剪所有权做别名更新，不重写已经选择的连续关系。

## 人工修正双边资料

共用概览和精确 Native 编辑器提供“启用双边边界”、进入淡化截止、退出淡化起点。两个数值是**录音源绝对毫秒**；进入起点、退出终点和终止位置仍锚定该行已有开始／结束，不替代 P/C/overlap。波形概览显示两个窗口；精确视图显示规范化范围。打开旧行不会自动创建 profile，只有明确启用才创建，关闭也必须明确操作。经典 UTAU 标量局部编辑不提供这些原生控件。

普通行范围改变而双边字段未动时，共用 Session 按原有范围编辑语义仿射映射继承窗口；明确修改双边值则按新范围严格校验，不二次映射。移动相邻边界同样处理；源注音分割将物理窗口裁剪到新行范围并保留 profile 和连接身份；合并只取第一行进入与最后一行退出。混合新旧行时，不存在的外沿为零时长，不猜一段淡化。上述源标注重定义与项目中无损切片不同：项目切片不重写标注资料，沿组合共同时钟保持实际淡化连续。

这些操作复用已有草稿、撤销／重做和显式保存，不因打字写源文件。Native 当前音符目的地只改对应音符的局部快照，源 OTTO 不写入。非法数值、未知版本或过期引用不修改已提交草稿。

## 保存和保护

预览无磁盘写入。每次发布追加独立变体，既有变体即使最早来自自动注音，也不被无确认覆盖。物理 WAV 不复制／改写。Root OTTO 的修改使用既有 `OttoMaterialIO::replaceAudio/saveDocument`，保留原文修订指纹并原子提交；提交前重新检查源文件 SHA、取消状态和主界面预检。

存在旧 OTO 而尚无 Native OTTO 时，先使用既有显式迁移操作，避免新建部分 OTTO 静默遮蔽旧库。当前被使用而不能安全确定独立变体的音源根也会拒绝；这不是自动更新已有工程调音的入口。

文件夹中部分失败会明确列出，只能确认保存成功预览。偏好登记失败时文件仍保留，可用既有重试登记菜单，不删除已写入的 OTTO。并发外部写入与主界面发布门闩的边界分别处理，不声称跨进程／MCP 全局事务原子性。

## 验证口径

真实录音的 C++ ASR、TIFA、字典分组、规范 OTTO 发布、冷启动会话、实际素材放置及 HJPX 保存重开分别检查。运行成功不等于音素文字百分百正确：文件名、旧 OTO 的采样别名也不自动作为经过核实的转写真值。预览必须允许检查与显式纠正，不用合成波形假充人工日语语音准确率证据。

本阶段没有修改原有音频 DSP，也未重测 teio／东京泰迪熊。具体本轮结果保存在开发包 verification 和工作区 validation/japanese-annotation；失败构建／用例保留，不覆盖成“全部通过”。
