## 操作与边界

1. UST／USTX 导入 HachiShifter 原生轨后，选中后再次短单击乐谱音符或使用右键“替换素材”，按音符歌词／发音查询已登记素材。Ctrl 多选后打开其中一个音符，按实际时间顺序分配。候选优先显示确切连续源行：`da/re` 可以选择 `da_re_mo.wav` 的 `da → re`，不使用 `mo`；剩余 `ga` 单独选择。也可逐个替换，实际相邻同源行经同一规划器重建共享时钟。
2. 名字相同但文件、audioId 或行 ID 不同的候选由用户明确选择。不能按文件名拆音、凭别名猜变体或把滑音连接当成同源证明。所有选择先暂存；Esc／取消不改工程，最后一次选择只做一次音乐撤销。工程修订、绑定或源行失效后拒绝提交。
3. 保留音符 ID、绝对乐谱起点、长度、音高、歌词及导入参数。完整源支持区通过受保护辅音和可伸缩元音的单调时钟映射到乐谱；明确的目标 P 和辅音速度参加映射，缺失 P／O／速度不伪造。UST 原始 O 和包络字段保留；不把目标 O 覆盖源标注 O，也不增加另一套 UTAU 尾裁剪公式。源边缘与拼接增益仍归既有原生边缘／包络权威。
4. beat 0 前的完整先行支持可以用于试听和默认全曲导出；只增加文件的前置音频，不移动音乐时间。候选“试听”复用 Main 原音传输，连续候选仅播放选定源行并集，不合成、不写音频、不混入未选的后续发音；结束／取消／换候选恢复原位置且不自动恢复歌曲播放。
5. 新 Melodyne 导入的材料转换默认 C=P。若原工程依赖隐式时钟，先冻结旧时钟，再同步目标锚点；不改写已保存旧 HJPX 的既有音乐、曲线和源时钟。
6. 有确切物理源、真实交叠且能证明两个子源所有权的原生音符，工具栏“强制连接”和右键菜单 24 复用 `forceNativeConnection`：建立非破坏性的 `native-overlap` 连续素材与交叠滑音。保留完整身体、源窗和作者淡入淡出，切割线中间留口；移动后按当前交叠重新解析。关闭滑音仍保留素材结构与交叉淡化。无声／气声不造音高；协议乐谱／声库路径不冒充物理原生源。

## 单一动作权威

- `MaterialPronunciationCatalog::matchSequences/resolve`：只读确切候选与提交前重新校验。
- `MainMaterialSourcePicker.inc`：Main 持有异步会话，索引／解析使用拥有生命周期的执行器。预览与提交共用候选身份解析；预览请求带会话序号，取消／关闭后不得迟到启动。
- `NativeSourceReplacementPlan.h`：纯时钟规划；`ProjectModel::replaceNotesMaterialSources` 是批量提交权威，单音乐谱替换委托它。`nativeScoreMaterialAligned` 为显式新语义，旧工程缺省不启用。
- `NativeOverlapConnection.h`：物理结构和现场交叠证明；模型、渲染和视图共用它。视图展开前缓存小型边界／共享滑音投影，不能拿展开后的显示子片伪造原始结构证明。音频同样使用物理轨作为新式交叠的滑音及缓存键权威，不改变没有该连接的旧路径。
- `NativeSourceEdgePlan`／AudioEngine：边缘增益、作者包络和导出；显式交叠不再叠加另一层自动平滑增益。默认导出 `(0,0)` 不能被负先行错误解释为“到音乐 0 截止”。
- 原生已登记行的源 F0 使用同次 FCPE 推理的整文件声学事实，而不是从 GAME 语义分段覆盖倒推。GAME segmenter 含实际参与边界输出的未固定种子 `RandomUniformLike`，可能随机把有 F0 的覆盖判成 rest；这不应抹掉用户明确选定源行的真实音高。`preserveFullSourcePitch` 默认关闭，Main 文件任务显式保留事实以支持迟到合并的源票据；只有该类源票据消费 `sourcePitchNotes`，普通分段音符仍不变。不重复 FCPE 推理、不改模型或阈值、不填补实际 unvoiced。已登记替换的等待状态只允许精确源票据消费：普通 trim／语义回调即使持有同一文件哈希也不能抢先完成绑定。增量重绑已有完整 F0 的所有者时，仍通过同一票据重新应用缓存事实，不能重置音符声学状态后又漏掉测量。仅改为单工作线程并不能消除模型自身随机性，不能谎称修复了后端共享 scratch 竞争。
