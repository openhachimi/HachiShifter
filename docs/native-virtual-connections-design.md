## 最新识别补充：一个衔接音可被非完全切割为两个片段

## 最新操作约束：移动不拆链（用户明确补充）

建立后，虚拟连接与非完全切割具有相同的持续绑定操作语义。单音或组的上下移调、左右移动不会自动断开、交换成员顺序或改接最近音；只有明确解除操作断链。拓扑由确切成员 ID 与原有向次序决定，不随几何重排而重建。

这替代早期“移开后视为失效连接”的设想。新建时保守拒绝不明声部与空隙是候选选择政策，不能被拿来删除已建立组。移动后的相邻支持/伸缩与交接应按当前源时钟重投影：超出原重叠时仍保留绑定，不伪造源声音，更不能因纯几何限制让整轨静音。现已拆分 `NativeVirtualResolveMode::newSelection` 与 `retainedConnection`：新建仍保守验证，已建立关系在 render/重新启用时按固定 ID 解析，允许空隙、时间反向和嵌套，不按当前横坐标改连。真实支持上的贡献仍归同一组分配，无支持的区间不生成样本；贡献权重仅在当前实际发声成员间分配，不是 PCM 响度归一化。尚需继续完善与同源非完全切割等效的邻接伸缩、移动后参考滑音和视觉手柄；当前保留空隙而不造音的行为不能冒充已经完成无缝时间适配。移动专项入口 `--smoke-native-virtual-move out` 检查组 ID、方向、实际回调可听、原生拖动模型路径、撤销/重做和冷重开。

## 权威边界

- 物理源/登记身份与虚拟关系分开，不能改写为同源连续素材，不烘焙多个 WAV。
- 普通音符保持各自源时钟、支持范围、音高及包络；组只管理有向连接、交接窗口和贡献权重。
- 原同源非完全切割走旧 authority。旧 native-overlap / force 编辑路径保持兼容，不因名称变化自动重算旧工程。
- 自动发现候选与提交分开；歧义、多声部或失效端点必须明确提示，不猜接最近音符。
- 无声片段可以有参考滑音图形，但不能因此变成有声/F0。自动滑音只局部改变真实有声目标，手调优先。

## 两半桥的实际候选检测（保守、仍待真实试听验收）

MelodyneImportResult 新增 `continuousSourceJoins`，在原图释放前保留确切 note/element/source 对应、相向 join、pitch/amplitude/phase 布尔。多音频组件、缺乏明确 sampleRate/startSampleIndex/time function、需要默认或截断才能构成正长度的源映射不当作肯定证明。记录本身的 `transitionIdentified=false`，不以任意 join 直接定性。

`NativeSplitTransitionDetection.h` 在原始事实基础上检查：短且实际连续的两个源片段，前半有相邻稳定有声证据，非两个稳定同音高元音，真实源切点附近存在相对双肩的持续能量谷，且只有一组正常左右端点通过四片段规划。源身份/源切点/目标切点均须一致；左右正常音本身重叠合法，另外的声部仍受保护。名称无关、呼吸与无F0前辅音不吞并、重复竞争假设跳过。条件属于当前保守置信政策，不能保证每个真实衔接音都命中。

开启自动虚拟连接时，Main 将保留的原始 join 传给共享发现器，优先提交检测到的四物理成员逻辑桥，再处理原三段和双段候选。虚拟优化默认关闭不产生组。身份登记是独立政策：既有 `import.autoRegisterTransitions` 开启时 Main 即使虚拟优化关闭，也将识别结果存到 `ProjectData.logicalTransitions`，不改两个半片段的 kind/P/C/voicing/clock。`NativeLogicalTransitionIO.h` 与组共用严格源证据 codec，保存完整源范围和真实中间切点；注册音乐/源指纹排除此纯身份元数据。单纯身份登记不会接入新的音频权重。

明确注册素材时，`ProjectMaterialRegistrationFacts::derive` 通过精确源切点和原 note/owner 身份合并两个 source facts 为一条完整 transition 行，保留两个 member locator；后续仍由原 prepare/stage/publish 权威写 OTTO，一行有一个真实中间分界、无 P/C。原两半的本地播放快照保持。两条标注路径现共用 `NativeLogicalTransitionSource.h::nativeLogicalTransitionSourceRow`：导入先在原始快照识别逻辑桥，再由 SampleSettings 在已有 atomic save 前，仅将得到确切源证明的两条新生成半行整合为同一个完整 transition 行；明确注册也使用同一个行构造权威。其他行不改，重复整理不重复插入，源/切点冲突需要独立变体时给出警告而非任选一个覆盖。不会为了库标注改写原两个播放片段或把完整 shape 塞进半片段。

`--smoke-native-logical-transition-registration out` 扩展至17项通过：导入 sidecar 与明确注册均冷读一条完整衔接音行、真实切点一致、两半原请求和精确源时钟不变、不误删其他行、重复幂等、已有原子发布、HJPX 重开及原 WAV 哈希。实际演唱/真实工程分类准确度仍需用户验收。

`--smoke-native-split-transition-detection out` 的15项控制 PCM/导入数据专项通过。新增只读 `--inspect-mpd-split-transitions input.mpd output.json`，关闭递归媒体查找、不转换素材标注、不复制媒体、不渲染。实际 test1.mpd 在60秒上限内完成、无缺失素材、保留17对充分源连续事实、给出3个候选，核对 MPD SHA 不变；这些是待审核候选，不是已经人工确认的正确率/听觉结果。

## 辅音合并：同源纯规划基础（尚未接自动开关或持久拆回）

`NativeConsonantMergePlan.h` 接受与桥分类分开的“已识别齿/摩擦音”决定及原始连续源 join 证据。只规划同轨、同物理录音、确切相向元素关系、连续 source seam／target seam 的两个完整单元素 owner；明确无声轮廓必须存在，后段有稳定有声证据。排除呼吸、逻辑桥任一半、既有虚拟组成员、已绑定/局部编辑源。其他独立录音的重叠不被删掉；同录音另一放置跨过真实切点会拒绝。

规划保留元音 note/owner ID 与音高中心、dense 趋势参数，前段只作为 UV 先行加入；源时钟逐原始非线性节点拼接、不重估 warp。新 P=实际源切点，C=元音原有效 P，否则 C=P。两个原片段完整复制到规划输出，尚不是已经持久化的拆回记录。元音 vibrato 使用同一原时钟重参数化，不把前置时长算进颤音；内部旧 crossfade 不再作为两音边界，外边缘参数保留。当前对不同表达增益/非空增益包络/高级包络明确拒绝，不悄悄丢失；后续需支持或提示，而不能假称所有候选都能自动合并。

入口 `--smoke-native-consonant-merge-plan out` 检查 P/C、真实 cut 对拍、原 source knot、UV/元音趋势与颤音、原片段保留、已有 P→C、无识别决定/逻辑桥/呼吸/空分析/错源切点反例。纯规划不发布文件、不改工程，不能代表默认关闭导入功能或冷重开拆回已经完成。

## 辅音合并提交与持久原片段拆回（已接基础，自动开关尚未接）

`ProjectModel::mergeMelodyneConsonant` 复用纯规划后，在一个撤销事务内移除前辅音 owner、保留元音 ID 的合并 owner，并生成 `consonantMerges` 记录。两个完整原 owner/NoteData 使用**现有 toValueTree/fromValueTree 二进制格式**存档，不另写第二套音符 codec。存档清空物理路径，由当前合并 owner 的唯一源路径与原 WAV SHA 证明恢复，已注册搬移后的同字节源也可拆回，不引用陈旧原路径。档案尺寸有界、版本/身份/编码校验；当前仅接受未建立显式图编辑的原始导入片段，不能悄悄丢弃已有连接曲线。

`restoreMelodyneConsonant` 恢复原始 ID、位置、曲线、淡化与源时钟，不是通用切分产生两个新音符。恢复本身可撤销；合并后已编辑时拒绝静默覆盖，只有显式确认放弃合并后修改才还原原片段。若已加入虚拟组则先明确解组，若源文件字节不符则拒绝。原始源 PCM 始终不写。当前没有直接覆盖原始作品文件或安装程序。

`NoteData.consonantMergeId` 是明确合并意图，SampleSettings 转换通过现存存档验证后保留独立 P/C：不再把 C 重置为 P，也不把 target C 当成 source P。默认未合并音符仍沿用原转换路径。`--smoke-native-consonant-merge-model out` 16 项通过：实际原子提交、一步撤销/重做、HJPX 冷重开精确拆回指纹、确认保护、同字节源搬移、导入 OTTO 独立 P/C、转换前后 source/target 请求及原 WAV SHA。它尚不是自动齿音识别、默认关闭导入选项或真实演唱试听验收。

## 默认关闭的辅音自动合并与恢复菜单（基础接入）

`NativeConsonantMergeDetection.h` 先验证纯规划需要的原始同源 join/clock/explicit-UV/稳定元音等结构，再读取最多0.5秒的真实起音 PCM：1500Hz 高通能量占比、过零率和非周期性作为齿/摩擦噪声支持。Melodyne sibilant marker 只降低保守门槛，不单独决定身份；缺 marker 要求更强高频噪声。高频周期纯音即使漏检 F0 也拒绝，呼吸 kind、空分析、逻辑桥半段和竞争候选均跳过。不按名字猜 sh/ts，也不宣称此启发式是语音识别或零误判。

## 导入非完全切割的移动语义（用户报告修正）

用户指出：Melodyne 工程导入后的非完全切割音符，上下左右移动时应保持连接，与 Melodyne 行为一致，而不是一动就分开。此前各轮只证明了“连接记录仍在”，没有证明实际接缝不断，这是真实缺口，本轮已修正同源情形。

`NativeCoupledSelectionMove.h` 只按导入的真实证据建立联动关系：同一 `materialSourceUsageGroupId`、同一物理录音、相向的 `connectedToNext/Previous` 与 `glideConnectedToNext/FromPrevious`，且目标接缝与源接缝都在 1e-6 内吻合。对选区做传递闭包；选区未触及任何此类关系时完全不介入，原独立移动路径不变。联动本身复用既有共享边界／加权区段的 warp（临时 linked 投影），随后恢复原物理 owner ID 与音频范围标记，不新建 DSP、不落盘复合 owner、不产生第二个移动写者。`ProjectModel::moveNativeNotes` 先尝试该投影，保持单一权威与单次撤销。

**范围更正**：首版把所有虚拟组边也刚性联动，这与已审核的跨源规则（成员可分离／交叠／交叉，仅凭 ID 与方向保持连接）冲突，已收窄为：只有 `splitTransition` 的前后两半、且两者确实共用同一物理录音时才联动。普通跨源虚拟成员不被几何拉伸。

同时修复了一个真实混音缺陷：`virtualBindingAt`／`fadeEnvelope` 原先按 clip 局部时间取组权重，而混音按逐样本位置取样；把一半桥拖到与另一半重叠时产生最大 0.0605 的 PCM 偏差。两者现统一使用同一采样时钟，移动后的五个用例偏差回到约 1.1e-8。`nativeVirtualContributions` 在真实重叠处由实际进入的半段取胜（不造平均假接缝），并只在真实可用支持之间分配，两半被拖到重叠时仍只算一个逻辑桥角色。

`--smoke-native-partial-cut-move out` 15 项通过：左右拖动两侧、单独移调、移动＋移调同时，目标与源接缝均保持在 1e-7 内；单次撤销/重做；源支持总量守恒；两个 owner 时钟严格递增；无关音符不被带动；跨源组成员移动不拖动伙伴且成员与顺序不变。四片段混音入口另增 5 个移动用例的真实渲染比对。真实工程中的人工拖动与试听仍未完成，不能据此宣称用户诉求已全部满足。

## 真实拖动手势路径验证（补齐此前只测 Model 的缺口）

此前各轮都直接调用 `moveNativeNotes`，而真实界面手势并不完全走这条路：`PianoRollComponent` 在水平位移近似为零时改调 `transposeNotes`，即**纯上下拖动不经过联动路径**。用户明确要求上下移动也保持连接，因此必须单独验证。核对 `transposeNotes` 实现：它只改 `midiNote`／音高控制点，完全不触碰时间、起点与源时钟，故不会破坏接缝——这是按实际实现确认，不是假设。

`--smoke-native-partial-cut-drag-gesture out` 用真实 `juce::MouseEvent` 驱动真实组件（按下、两次拖动、抬起），覆盖纯垂直（+2 行）、纯水平（+0.15 秒）与组合（−0.1 秒、−1 行）三种手势：目标接缝与源接缝均为 0，两个 owner 保留，源时钟仍严格递增，7 项通过。为按音符 ID 精确命中可点击块，`PianoRollComponent.h` 增加两个只读诊断访问器。

## 自动滑音的真实音频验证（此前只验到请求层）

既有 `--smoke-native-virtual-pitch-request` 只验证路由、UV 掩码与缓存键，**没有任何证据表明滑音真的弯曲了渲染音频**。新增 `--smoke-native-virtual-glide-audio out` 用自相关直接测量真实渲染输出的基频。

实测（8 项通过）：两个未连接素材基线分别为 57.01 与 64.07（即 A3/E4）；开启自动滑音后依次为 57.01 → 57.83 → 60.52 → 63.14 → 63.95，平滑单调且限定在交接窗口内，远端保持各自音高（误差 <0.6 半音）；关闭连接后 PCM 逐位还原。另直接打印生成曲线，确认为 0.775–1.125 秒间 57→64 的 71 个点，形状正确。

顺带观察：基线扫描在 t=0.95 处出现原始重叠冲突（音高塌到 45.01），而开启滑音的渲染平滑通过 60.52——连接实际上修复了该冲突。这是观察结论，不是验收结论。

**一处测量陷阱（属测试缺陷，非产品缺陷）**：最初夹具使用纯正弦源，渲染输出表现为整段音高紊乱（43/39/68/0，而电平正常），看起来像严重的新缺陷。在归咎该功能之前先做对照——不涉及任何连接的普通移调同样错误（请求 59 得到 64.07），证明问题不在滑音。改用类人声谐波叠加后全部恢复正常，对照移调精确读到 59.034。教训：纯正弦不是声码器分析的有效输入；报告缺陷前必须先跑"不启用该功能"的对照。

## 导出一致性（播放与成品必须相同）

播放与 `exportWav` 是两条独立路径，若连接只存在于播放中，成品会静默损坏。此前没有任何测试覆盖导出路径。新增 `--smoke-native-virtual-export-parity out`，从同一引擎实例分别经播放与导出产出音频并逐样本比较。

实测（8 项通过）：开启连接时播放与导出最大差 1.19e-07，仅为 24 位量化误差，即所听即所得；导出文件本身测得 57.01 → 60.52 → 63.95，证明滑音确实进入成品而非只在监听中；关闭连接后导出与未改动原始音频**完全逐位一致（差 0）**；开启与原始导出确有差异（>1e-4），比较非空洞。夹具沿用上一节的类人声谐波素材。

另：多音符 owner 作用域（`da_re` 只连 `re` 不得压到 `da`）此前已在 `NativeVirtualMixerSmoke.h` 以真实 PCM 覆盖（未选中的 `da` 在成员支持之外逐位一致、逐样本权重限定于 `re`），本轮核实后未重复造测试。
